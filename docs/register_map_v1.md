# FPSAT Register Map, v1

**Status:** draft for review. Version 1 of the competition-standard interface between an entry and the competition runner.

An entry is a hardware design alone. It carries no host code. The competition runner parses the DIMACS file and drives every design through the registers below. This document is the only interface an entry has to satisfy. The key words MUST, MUST NOT and MAY are used in their usual normative sense.

## 1. Bus

- The design is a Wishbone B4 peripheral in the base SoC, with a 2 KB register window of 512 32-bit words.
- The SoC control plane (CPU, bus, network) runs at a fixed 50 MHz. The design runs in its own clock domain, at the frequency the entrant declares in `info.yaml`, generated by the SoC's PLL. The SoC bridges the two domains, so the design contains no clock-crossing logic and sees only its own clock.
- The SoC instantiates the entry as a Verilog module named `user_design` with these ports (the build finds the entry's top module, which is the one module whose ports match this contract exactly, or the module named by `top_module` in `info.yaml` when more than one matches, and renames it to `user_design`):

  | Port | Direction | Width | Meaning |
  |---|---|---|---|
  | `clk` | in | 1 | the design clock (the declared frequency) |
  | `rst` | in | 1 | reset |
  | `wb_cyc`, `wb_stb`, `wb_we` | in | 1 | Wishbone B4 request |
  | `wb_adr` | in | 9 | word address |
  | `wb_dat_w` | in | 32 | write data |
  | `wb_sel` | in | 4 | byte select |
  | `wb_dat_r` | out | 32 | read data |
  | `wb_ack` | out | 1 | acknowledge, registered: asserted one cycle after `wb_cyc & wb_stb` |

  Requests are single and not pipelined: `wb_stb` stays high until `wb_ack`.
- Word `n` is at byte address `4 * n` from the window base. All registers are 32 bits. Accesses are word-aligned and full-width.
- Reserved words (16-255) MUST read as 0, and writes to them MUST be ignored. Words 256-511 are the `MODEL_DATA` alias (section 3.6), and writes to them MUST be ignored.
- Words 10-11 belong to the SoC. The SoC wrapper answers them itself and never forwards them to the entry (section 9), so the entry does not implement them.
- A write to a read-only word, and a read from a write-only word, MUST have no effect. The value returned by a read of a write-only word is undefined.

## 2. Register summary

| Word | Name | Access | Contents |
|---|---|---|---|
| 0 | `CTRL` | W | bit 0 `START`, bit 1 `ABORT` |
| 1 | `STATUS` | R | bit 0 `BUSY`, bit 1 `DONE`, bit 2 `REJECTED` |
| 2 | `RESULT` | R | 0 unknown, 1 SAT, 2 UNSAT |
| 3 | `NVARS` | W | number of variables |
| 4 | `NCLAUSES` | W | number of clauses |
| 5 | `NLITS` | W | number of literals, not counting terminators |
| 6 | `LOAD_DATA` | W | literal stream |
| 7 | `MODEL_DATA` | R | satisfying assignment, one literal per read |
| 8 | `MAGIC` | R | identification |
| 9 | `VERSION` | R | register-map version, 1 for this document |
| 10 | `CYCLES_LO` | R | low half of the solve-cycle counter (SoC-owned, section 3.8) |
| 11 | `CYCLES_HI` | R | high half of the solve-cycle counter (SoC-owned, section 3.8) |
| 12 | `MAX_VARS` | R | declared capacity: variables |
| 13 | `MAX_CLAUSES` | R | declared capacity: clauses |
| 14 | `MAX_LITS` | R | declared capacity: literals |
| 15 | `INFO` | R | design-defined reason code, for logs only |
| 16-255 | reserved | | read as 0 |
| 256-511 | `MODEL_WINDOW` | R | alias of `MODEL_DATA` (section 3.6) |

## 3. Register definitions

### 3.1 `CTRL` (word 0, write-only)

| Bit | Name | Effect |
|---|---|---|
| 0 | `START` | Begin the solve. Only effective when the design is idle (`BUSY` = 0 and `DONE` = 0). A `START` in any other state MUST be ignored. |
| 1 | `ABORT` | Stop whatever the design is doing and return it to idle. Accepted in any state. See section 5. |

If both bits are written together, `ABORT` wins and `START` is ignored. The other bits are reserved. They MUST be written as 0, and the design MUST ignore them.

### 3.2 `STATUS` (word 1, read-only)

| Bit | Name | Meaning |
|---|---|---|
| 0 | `BUSY` | A solve is running. |
| 1 | `DONE` | The solve finished and `RESULT` is valid. Held until `ABORT`. |
| 2 | `REJECTED` | The design found it cannot hold the instance, and has stopped. Held until `ABORT`. |

`BUSY`, `DONE` and `REJECTED` are mutually exclusive. When all three are 0, the design is idle. The other bits read as 0.

### 3.3 `RESULT` (word 2, read-only)

| Value | Meaning |
|---|---|
| 0 | unknown: the design has given up, or has no answer |
| 1 | SAT |
| 2 | UNSAT |

`RESULT` is meaningful only when `STATUS.DONE` = 1. A design that gives up MUST still set `DONE` and report 0. It MUST NOT leave the solve running just to avoid reporting an answer. Any other value of `RESULT` is invalid (section 7).

### 3.4 `NVARS`, `NCLAUSES`, `NLITS` (words 3-5, write-only)

The size of the instance, written before the clause stream. These are the values from the DIMACS file: `NVARS` and `NCLAUSES` come from the `p cnf` line, and `NLITS` is the total number of literals over all clauses, not counting the 0 terminators.

Writing any of them while the design is not idle MUST be ignored. Writing `NVARS`, `NCLAUSES` or `NLITS` resets the load position, so a stream is always preceded by the three sizes.

### 3.5 `LOAD_DATA` (word 6, write-only)

The clause stream, loaded after the sizes and before `START`.

- Each write is one signed 32-bit DIMACS literal: a variable `v` in `1..NVARS` is `+v` and its negation is `-v` (two's complement).
- A write of 0 ends the current clause.
- The stream is exactly `NCLAUSES` clauses. The total number of words written is `NLITS + NCLAUSES` (the literals, plus one terminator each).
- The runner sends clauses in file order, and literals in file order within each clause. A design MUST NOT depend on the order, but it may rely on the stream being well formed.
- Writes while the design is not idle MUST be ignored.

The load is not timed. The design is expected to accept writes at bus speed. It MAY stall the bus with Wishbone wait states.

### 3.6 `MODEL_DATA` (word 7, read-only)

The satisfying assignment, read after `STATUS.DONE` = 1 and `RESULT` = 1.

- The first `NVARS` reads return one literal per variable, in variable order `1..NVARS`: `+v` if the variable is true in the model and `-v` if it is false.
- Reads after that return 0.
- Writing `NVARS`, `NCLAUSES` or `NLITS` while idle, or writing `ABORT`, restarts the read position at variable 1. Size writes in any other state are ignored (section 3.4) and leave the read position alone.
- The model need not be partial. A variable the design leaves unconstrained MUST still be reported with either sign.
- Outside `DONE` with `RESULT` = 1, a read returns 0.

**Bulk readback (`MODEL_WINDOW`, words 256-511).** The SoC's bus bridge reads a burst from consecutive addresses, so it cannot read word 7 repeatedly. To stream the model, every read of words 256-511 MUST behave exactly like a read of word 7: it returns the next literal and advances the read position, whatever the address within the window. A burst of up to 256 consecutive words starting at word 256 therefore returns the next 256 literals. In hardware this is the decode `wb_adr == 7 | wb_adr[8]`. Reads of word 7 and of the window share one read position, so they can be mixed. The runner uses the window for bulk reads.

The runner checks the model against the original clauses of the DIMACS file.

### 3.7 `MAGIC` and `VERSION` (words 8-9, read-only)

`MAGIC` MUST read `0x46505341` (ASCII `FPSA`). `VERSION` MUST read `1`. These are part of the design's registers and identify an entry that implements this document. The pre-flight check and the runner refuse a design that reports any other pair.

### 3.8 `CYCLES_LO` and `CYCLES_HI` (words 10-11, read-only, SoC-owned)

A 64-bit count of design-clock cycles, `CYCLES_HI:CYCLES_LO`, kept by the SoC wrapper around the entry (section 9). The entry does not implement these words. It never sees accesses to them, cannot change what they read, and so cannot misreport its solve time. Writes to them are ignored.

The counter starts at an accepted `START` and stops when the solve ends. The solve time for scoring is `cycles / f_design`, where `f_design` is the design clock's achieved frequency recorded for the build (section 9). To read a 64-bit value while the counter is running, read `CYCLES_HI`, then `CYCLES_LO`, then `CYCLES_HI` again, and retry if the two `CYCLES_HI` reads differ. After the counter has stopped no retry is needed.

### 3.9 `MAX_VARS`, `MAX_CLAUSES`, `MAX_LITS` (words 12-14, read-only)

The size of the largest instance the design claims it can hold, in the same units as `NVARS`, `NCLAUSES` and `NLITS`. They are constants, and they are valid at any time, including before the first instance.

Before loading, the runner compares each instance with them. If `NVARS > MAX_VARS`, `NCLAUSES > MAX_CLAUSES` or `NLITS > MAX_LITS`, the runner skips the instance. The design is never started, the instance counts as unsolved (not wrong), and it is scored as a time-out. A design MAY also set `STATUS.REJECTED` after `START` if it discovers it cannot hold an instance within its declared capacity, for example because of how the clauses are distributed. The runner treats that the same way: unsolved, not wrong.

A design MUST NOT declare a capacity it cannot hold. A design that claims to hold an instance and returns a wrong answer is scored as wrong.

### 3.10 `INFO` (word 15, read-only)

A 32-bit, design-defined reason code. The runner copies it into the per-instance record whenever `STATUS.DONE` is set with `RESULT` = 0, or `STATUS.REJECTED` is set, so entrants and organizers can see why a design gave up. Its values have no meaning to the competition: they are never scored, and the runner never branches on them. A design with no codes reads 0.

## 4. Instance sequence

For each instance, the runner does the following.

1. Reads `MAGIC` and `VERSION` once per board session, and `MAX_VARS`, `MAX_CLAUSES` and `MAX_LITS` once per design.
2. Skips the instance if it exceeds the declared capacity (section 3.9).
3. Writes `ABORT`, so that the design is idle with no state from earlier instances.
4. Writes `NVARS`, `NCLAUSES`, `NLITS`, then streams the clauses to `LOAD_DATA`.
5. Writes `START` and polls `STATUS`.
6. When `DONE` is set, reads `RESULT`, `CYCLES_HI` and `CYCLES_LO`. For SAT it reads the model from `MODEL_DATA`. For `REJECTED` or a `DONE` with `RESULT` 0, it reads `INFO`.
7. While `BUSY`, polls `CYCLES`. If it reaches `T * f_design` before `DONE` or `REJECTED`, writes `ABORT`, records a time-out, and moves on.

## 5. Abort and reset

`ABORT` is the only reset, and a design MUST implement it. It makes the design idle in every state, including mid-solve and mid-load, and with no rebuild or reprogramming. After an `ABORT`:

- `STATUS` reads 0, so `BUSY`, `DONE` and `REJECTED` are all 0.
- All instance state is cleared: the loaded formula, learned clauses, the model position, and anything else that could change a later answer. A second instance must give the same answer as it would on a freshly programmed board.
- `RESULT` and `INFO` read 0.
- `MAGIC`, `VERSION` and the capacity registers are unchanged.

The design SHOULD be idle within 1,000 design-clock cycles of the write. It MUST be idle before accepting a new `NVARS`, `NCLAUSES`, `NLITS` or `LOAD_DATA` write. The runner waits for `STATUS` to read 0 and, if it has not done so within 1 s, treats the board as failed (section 7).

The pre-flight abort smoke test (start, abort, back to idle with no rebuild) checks this, and also solves a second instance afterwards.

## 6. Reset and board state

A board is programmed with the entry's bitstream once per run, and the runner does not reprogram it between instances. Abort therefore carries the whole burden of isolating instances. Designs MUST NOT keep state between instances, for example learned clauses, phase or activity scores, that survives an `ABORT`.

## 7. Invalid behavior

The runner scores an instance as invalid, which is penalized at 2T, when any of the following occurs after `DONE`:

- `RESULT` is not 0, 1 or 2;
- `RESULT` is 1 and the model has a literal outside `1..NVARS` in magnitude, repeats or omits a variable, or does not satisfy the original clauses;
- more than one of `BUSY`, `DONE` and `REJECTED` is set.

A wrong UNSAT, `RESULT` = 2 on an instance whose known result is SAT, is handled by the scoring rules: it is disqualifying in the final round.

A design that does not return to idle within the abort deadline (section 5) is a failed board. The runner records the instance as a time-out, reprograms the board, and continues.

## 8. Conformance

A design conforms when it passes the register-map checks of the pre-flight command, which cover:

1. `MAGIC` and `VERSION` read correctly.
2. Capacity registers are non-zero and constant.
3. Reserved words read 0, and a 256-word burst read of the `MODEL_WINDOW` after a SAT result returns the same literals as 256 single reads of word 7.
4. `STATUS` is idle after reset and after `ABORT`.
5. A small SAT and a small UNSAT instance solve correctly, including the model for SAT.
6. An instance larger than the declared capacity is skipped by the runner (the checker verifies the registers, not the design's behavior on the oversize instance).
7. Start, abort, back to idle, and then a correct solve of a second instance.

The solve-cycle counter (section 3.8) is the SoC wrapper's, not the entry's, so it is checked by the runner's own self-test and not by this list.

A reference testbench (simulation) accompanies this document. It lives with the template repository.

## 9. Solve-time measurement (SoC side)

**Platform status:** the wrapper counter described here is not in the SoC today. It is a required platform change, and until it lands the runner measures time on the host.

Solve time is measured by the SoC, outside the entry. The SoC's own module around the entry (the wrapper) sits on the design side of the clock-domain bridge, in the design clock domain, between the bridge and `user_design`. It passes every access through to the entry, except words 10-11, which it answers itself.

- **Counter:** a 64-bit counter of design-clock cycles. It cannot be written by the entry, and accesses to words 10-11 are never forwarded, so the entry cannot see or change it.
- **Start:** the counter is cleared to 0 and starts when the wrapper forwards a `START` write while the last `STATUS` it observed was idle. Loading is never counted.
- **Stop:** whenever the bus to the entry is idle, the wrapper reads `STATUS` from the entry itself. It stops the counter when it sees `DONE` or `REJECTED`, and on any `ABORT` write. The counter keeps its stopped value until the next accepted `START`. The detection delay is a few design-clock cycles. The entry influences the stop only through its own `STATUS`, the same trust placed in `RESULT`.
- **Read:** the runner reads words 10-11 through the normal register path, after the counter has stopped, and while `BUSY` to enforce the limit.
- **Time:** solve time in seconds is `cycles / f_design`. `f_design` is the achieved frequency of the design clock, which is what the PLL actually produces. It can differ from the requested frequency by up to the PLL solver's tolerance (about 1%), so the build MUST record the achieved frequency, not the requested one, in the build record (C4), and the runner MUST divide by that value.
- **Limit:** the runner enforces the time limit `T` = 5,000 s by aborting once the counter reaches `T * f_design` cycles. Overshoot is the runner's polling delay, and a timed-out instance is scored as `T` regardless.

## 10. Differences from PigWeedSAT

PigWeedSAT (the baseline entry) implements a different register map, with config registers at words 2-11 and a memory window for loading. To enter, it is wrapped by an adapter that implements this map. That work is a later task, and it does not change this document.

## 11. Changelog

- **v1:** first draft. The solve-cycle counter lives in the SoC wrapper and counts design-clock cycles. It is read at words 10-11, which the wrapper answers itself. Time is `cycles / f_design`, with the achieved PLL frequency recorded at build time. `MODEL_DATA` is aliased across words 256-511 for bulk readback, as in PigWeedSAT.
